## 0.6.0 — 批量导出 + 演示参考物（2026-09-16）

主题：**把"逻辑固定、容易漏项"的批量输出交给工具**，并补上一批可复跑的成规模参考物。

### 新增 `pixsmith export`

```bash
pixsmith export scene.json -o out/ --sizes 512,64,32,16 --svg \
        --mono '#0A1730' --mono-light '#FFFFFF'
```

一轮出齐「尺寸阶梯 × 单色墨 × 矢量」。为什么值得单独做：

- **矩阵是固定套路，但手工循环必漏项**。真实踩过的坑：只做了深墨单色版，
  忘了单色标识的标准用法是"浅底深墨、深底白墨"——深墨压在深底上就是没画。
- **单色改写按 `Param` 声明的类型动手，不靠参数名猜**，并**保留各自透明度**
  （丢掉透明度的后果不是"少个属性"，而是抗锯齿边缘变成硬边，小尺寸下很明显）。
- **覆盖不到的多色参数会报警**（新增 `_mono_is_clean()` 自检）：`points` 类型的
  色阶列表改写不到，渲染后立刻数一下"不透明像素里有几种 RGB"，多于一种就报出来。
  这类失败本来是**静默**的——图照样出得来、退出码照样 0，只有真把两种墨印在同一张纸上才露馅。
- `--sizes` 支持 `N`（方图）与 `WxH`；省略时只用场景自己的尺寸，
  也就是退化成「`render` + 矢量 + 单色版」，不擅自决定用户要哪几档。

### 新增演示参考物 `examples/showcase/`

两份**成规模**的生成脚本（不是教学示例，是可以照着改的参考物）：

- `make_logos.py` —— 5 个标识方案 × 尺寸阶梯 × 双单色墨，坐标全按 0–1 比例，
  同一段代码出任意尺寸；`small(s)` 在 ≤64px 主动降级（细线换胶囊拼边、细环换实心点）
- `make_themes.py` —— 21 个主题图标（电子制造 / 天气 / 节气 / IT 元素），
  全部由协议图元拼出，**每一个都能导出 SVG**

配套 `examples/showcase/README.md` 记下了四条约束与判据：只用协议图元才能出矢量、
形状不重叠单色版才成立、两种单色墨、小尺寸主动降级；
以及"怎么判断 16px 还认不认得"（IoU 对缩放，而不是直觉上的负空间占比 ——
后者在小尺寸下会因为栅格化把亚像素形状补胖而**反向**上升）。

### 其他
- `examples/` 补 3 个配方：`cover_report_1920` / `dashboard_2560` / `icon_gear_800`
- `AGENTS.md` 补 `export` 用法与两个坑（漏白墨版、单色不纯）

## 0.5.1 — 修掉"静默降级"的最后一层（2026-09-16）

主题：**`pattern` 元 op 的顶层键以前不校验，写错层级/写错名字的参数会被静默丢掉**。

### 修复：`pattern` 元 op 的未知键被静默忽略

现象 —— 参数忘了嵌进 `params` 时，渲染成功、退出码 0，而参数根本没生效：

```bash
echo '{"dsl":1,"size":[64,64],"ops":[{"op":"pattern","pattern":"star","points":3}]}' > t.json
pixsmith render t.json -o t.png      # 旧行为：✅ 成功；但 points 被丢掉了
```

**根因是四层校验里漏了最后一层**：

| 层 | 校验 |
|---|---|
| 场景顶层键 | ✅ `{"dsl":1,…,"typo":1}` 报错 |
| 图层键 | ✅ `layers:[{"ops":[],"typo":1}]` 报错 |
| 动词名 | ✅ `{"op":"nope"}` 报错 |
| 动词参数名 | ✅ `spec.bind()` 拒绝未知键 |
| **`pattern` 元 op 的顶层键** | ❌ **从未进过校验视野** |

`apply_ops` 对 pattern 只做 `spec.bind(args.get("params"))` —— 只有 `params` 会被 bind，
op 上其余键既不 bind 也不报错，直接被丢掉。

**为什么这个洞必须堵**：它正好踩中项目的立身之本「不静默降级」。
agent 看不见图，唯一的判据就是退出码与报告 —— 拿到 exit 0 和一张参数没生效的图，
它会当成成功结果继续往下走。而"参数写错层级 / 写错名字"是最高频的一类错误：
图案 `star` 用 `radius`/`rotate`，动词 `star` 用 `r`/`ang`，**同名不同参，极易串**。

**修法**：新增 `PATTERN_OP_KEYS = ("op", "note", "pattern", "params")`，
在 `check_verbs`（构造场景时就查，不等渲染）与 `apply_ops` 各查一次 ——
四层校验到此对称。报错沿用项目已有的"带可用清单"风格，
并对**名字对、层级错**这一种专门给一句可照抄的提示：

```
❌ [0] pattern op 不认识键 ['points']（可用：['op', 'note', 'pattern', 'params']）
    → points 是 'star' 的合法参数，但要嵌在 params 里：
      {'op': 'pattern', 'pattern': 'star', 'params': {'points': …}}
```

**这是行为变更**：以前能"跑通"的扁平写法现在会报错。之所以按修复而不是按破坏性变更处理 ——
写错的人拿到的本来就是一张错的图，只是没人告诉他。

### 其他
- `AGENTS.md` 常见错误表补一行（层级写错的症状与改法）
- 新增测试 `test_pattern_op_rejects_unknown_keys`，与既有四层校验的测试对称
- 测试 349 → **350**

## 0.5.0 — 本地调参台（2026-09-14）

主题：**补上"人用的那一半"**。

MCP 服务 agent，调参台服务人 —— 两边产出的是**同一个场景 JSON**，
所以手工调好的参数能直接给 CLI / agent / 存进 git。

### 新增 `pixsmith serve`
- 浏览器里选图案、拖滑块实时看效果（去抖 220ms）、一键复制场景 JSON
- 页面同时显示自检报告（通道跨度 / 四角取样 / 主色覆盖率 / hints）
- 支持位图与矢量两种后端；矢量端直接用 `<img src="data:image/svg+xml">` 预览
- 端口被占自动往后找空位

### ⭐ 控件自动生成
前端**不手写任何一个图案的控件** —— 全部从 `Param` 声明现推
（color → 取色器+hex 文本框；float/int → 滑块+数字框；bool → 开关；
points/stops → JSON 文本框）。
**所以加一个图案，调参台自动就支持它**，不用动一行前端代码。
`Param` 至此有了第四个消费方（前三个：CLI 校验、帮助文本、能力清单）。

### 安全（本地服务该有的三道）
- 默认只绑 `127.0.0.1`；改地址会二次提醒
- **Host 白名单**挡 DNS 重绑定；**Origin 校验**挡跨站 CSRF
- 画布上限 4096px、请求体上限 256KB

### 修复（平台差异的真 bug）
- **Windows 上 `SO_REUSEADDR` 允许抢占已被监听的口**（Unix 只用来跳过 TIME_WAIT）。
  端口探测照 Unix 写法写会把"已占用"误判成"空闲"，导致两个服务器绑同一个端口。
  改用 `SO_EXCLUSIVEADDRUSE` 探测，并把服务器的 `allow_reuse_address` 一并关掉。
  是 `test_port_falls_back_when_taken` 抓出来的。
- 客户端中途断开（浏览器取消请求）不再往 stderr 甩一整段 traceback。

### 其他
- `docs/32-本地调参台.md`；README / AGENTS.md / 能力边界 / test_docs 同步
- 零依赖：只用标准库 `http.server`，不需要 npm / 构建工具
- 版本 0.4.0 → 0.5.0；测试 331 → **348**

## 0.4.0 — MCP 接入（2026-09-14）

主题：**让 agent 把 pixsmith 当工具直接调用**，而不是每次拼一条 shell 命令。

### 新增
- **`pixsmith-mcp`**：MCP server（stdio 传输）。**手写 JSON-RPC，不引 `mcp` SDK** ——
  MCP 的 stdio 部分就是"换行分隔的 JSON-RPC 2.0 + 四个方法"，引 SDK 会破坏
  "只用 numpy"的承诺，也会让服务器无法离线单测。约 300 行。
- **3 个工具**（刻意少而准）：`spec` / `validate` / `render`。
  `spec` 用参数收拢了「列清单 / 看单个规格 / 看最小示例」三件事，而不是拆成三个工具 ——
  工具描述本身也占上下文，重叠的工具只会让 agent 选错。
- **`initialize.instructions`**：把工作循环与三条关键规程写进协议给的位置，
  而不是指望 agent 去翻 AGENTS.md。
- `tools/mcp_smoke.py`：起**真实子进程**走完整握手 + 三个工具；
  CI 里跑 `--console` 顺带验证控制台入口。单元测试喂 JSON 覆盖分支，
  冒烟验另一面（进程起得来吗、stdout 干净吗）—— 两者缺一不可。
- 库函数 `filters.resize()`（双线性、**alpha 感知**），供预览缩放用。

### 三个 agent 友好的设计决定
1. **`render` 默认回一张缩小预览图**：agent 看不见图是最大的障碍，
   给它一双眼睛比给更多数字有用。缩到 `preview_max_px`（默认 512）以内，
   不想要就 `embed_preview: false`。
2. **工具失败用 `isError: true`，不用 JSON-RPC error**：前者是内容块，**会原样交给模型**，
   它才能自己改正；后者在多数客户端里只会报一句故障。协议/传输层问题才用 JSON-RPC error。
3. **只暴露 JSON 快捷通道，不暴露 Python 创作通道** —— 服务器天然没有代码执行面。
   这是"能力分两条通道"的架构回报：需要给不可信输入一个安全沙箱时，
   声明式那层就是现成的沙箱。

### 安全
- 唯一写入面是输出目录：输出名只取 basename，路径穿越（`../`、绝对路径、盘符）一次挡掉，
  扩展名按后端强制纠正
- **stdout 只走协议**：工具执行期间 `sys.stdout` 重定向到 stderr，
  免得任何一句不经意的 `print` 冲坏 JSON-RPC 流（有测试守着）

### 修复
- `mcp_server.py` 少了 `if __name__ == "__main__"` 守卫 →
  `python -m pixsmith.mcp_server` **静默退出 0 且零输出**。
  这个失败最阴：退出码正常、没有任何报错。是端到端冒烟抓出来的。

### 测试
303 → **328**（新增 25 个 MCP 协议级用例）。

## 0.3.2 — 自检报告的误导性修复（2026-09-14）

主题：**修掉两个"让 agent 越查越偏"的问题**。同样来自对 agent 使用路径的自查。

### 修复：`--report` 的 `dominant_colors` 会误导
做封面时报告返回的主色全是中间调，端点色一个都没进 top-4，看着像参数传错了 ——
抽样一看渐变完全正确。**根因**：`dominant_colors` 回答的是「哪种颜色占的面积最多」，
而 agent 想问的是「我的参数生效了吗」。对角渐变的颜色分布是**梯形**的，
中间调占面积最多，top-4 必然是它们。

修法不是删字段（它在纯色 / 图标 / 条纹这类图上仍然有用），而是**给它配上能回答
真问题的探针，并让报告自己说出来**：

- 新增 `channel_range`（每通道 min/max）—— 设了红渐变，`r` 就该有跨度，跨度≈0 说明没生效
- 新增 `corner_colors`（四角取样）—— 渐变端点与方向的直接证据
- 新增 `dominant_coverage`（**主色覆盖率**）+ `hints`：覆盖率低时报告自己提示
  "这张图没有主色，别用 dominant_colors 判断"

阈值 **0.25 是实测标定的，不是拍的**：
纯色 100% · 纯色+图形 98.7% · 条纹 50.3% · 棋盘 50.5% · 星空 90.5%（有主色）
渐变 118° 12.9% · 渐变 90° 8.4% · 三色渐变 18.4% · 大理石 19.2%（没有主色）。
（顺带发现：`contrast` 在渐变场景天然极低（实测 0.03），**也**不能当"颜色不对"的证据，
已在 AGENTS.md 标出。）

### 修复：路径拼错的报错文不对题
`validate output/verify/typo.json` 报的是「没有名为 'output/verify/typo.json' 的图案」——
`_load_scene` 的启发式把不存在的路径当成了图案名。对 agent 来说，
**错误的报错类型比没有报错更费 token**：它会照着去改图案名。

改为**先路径后图案，不留猜的余地**：含 `/`、`\` 或已知扩展名（`.json` 等）的输入
一律按路径处理，不存在就报「文件不存在」并附上**解析后的绝对路径 + 当前目录 + 图案名写法提示**；
是目录也单独报错。顺带修掉 `render scene.json` 不带 `-o` 时会输出 `scene.json.png` 的怪名字。

### 其他
- `AGENTS.md` 的报告章节重写为「哪个字段回答哪个问题」的对照表
- 测试 293 → **303**

## 0.3.1 — agent 通路修复（2026-09-14）

主题：**修掉"让 agent 走弯路"的几处**。全部来自一次针对 agent 使用路径的自查。

### 修复
- 🔴 **CLI 漏捕 `UnsupportedOperation`**：该异常继承 `RuntimeError`，不在原来的
  `except (KeyError, ValueError, TypeError, OSError, JSONDecodeError)` 里 ——
  于是最好用的那句报错（"换后端 / 换方案"）被整段 traceback 埋掉，退出码还是 1 而非约定的 2。
  而 agent 最容易踩到它的动作，恰恰是"想输出 SVG"。已补。
- **错误消息多余引号**：`str(KeyError)` 会给消息再套一层引号
  （`❌ "没有名为 'x' 的图案"`），对按行解析 stderr 的 agent 是噪音。改取 `args[0]`。

### 新增
- **`AGENTS.md`** —— 给 AI agent 的操作手册。把三条关键规程显式写出来：
  ① 优先走 JSON 快捷通道、装不下再走创作通道；② 写图案必须声明 `requires`；
  ③ 渲染后用 `--report` 自查（agent 看不见图）。以前这些散在 docstring 与规划文档里。
- **`validate` 子命令** —— **只校验不渲染**，省掉 agent 一轮"生成 → 渲染 → 看报错 → 改"。
  可 `--backend svg` 提前知道能不能出矢量。
- **`--json-errors`** —— 错误输出为机器可读 JSON。
- **`spec --json` 可按需过滤**：`--only <key>` / `--kind` / `--category`。
  默认改为**紧凑 JSON**（去掉缩进）：全量 **50073 → 29105 字节**；
  `--only marble` 仅 **2808 字节**。
- `show` 现在**也能查动词**（以前 `show blur` 会报"没有名为 blur 的图案"）。

### 文档
- **重写 `docs/能力边界.md`**：原文停留在 v0.1，写着做不到 SVG / 矢量、没有真正的混合模式、
  没有模糊 —— 而代码早已支持。**一份说自己做不到的过期文档，会让 agent 主动放弃本来能用的能力，
  比没有文档更糟。** 顺带修掉一个引用了已废弃 API 名的条目。
- 新增**文档防过期测试**（`tests/test_docs.py`）：钉住文档的版本标记与能力计数，
  改代码忘了改文档会失败。这是根因修复 —— 加文档不会过期，加测试才会。
- 修正 `__init__.py` 的图案数（19 → 23）、`pyproject.toml` 的 description（不再只说 PNG）。

## 0.2.0 — 双后端 + 元能力（2026-09-14）

主题：**从"图案库"升级为"能力层 + 素材层 + 后端可替换"**。

### 新增：矢量后端（`svg.py`）
- `SvgBackend` 与 `Canvas` **接口对齐**，同一份场景可输出 PNG 或 SVG
  （PPT 自 2016 原生支持 SVG —— 这是"双后端"对汇报场景的直接价值）。
- 机制：一元算子 = 把已累积内容包进 `<g filter="...">`；`erase_disc` = 用 `<mask>` 抠洞。
- **23 个图案中 15 个双后端通用**；其余 8 个显式声明 `requires=("paint",)`。

### 新增：元能力（一元 / 二元算子）
- **一元算子**（`filters.py`）：`blur`（盒式×3 近似高斯，**alpha 感知**，前缀和 O(n)）、
  `adjust`（亮度/对比度/饱和度/色相/伽马，矩阵照抄 SVG 规范）、`posterize`、`solarize`、
  `invert`、`grayscale`、`grain`（带 seed，可复现）。
- **二元算子**（`blend.py`）：14 种混合模式，公式遵循 **CSS Compositing / PDF 混合模型**，
  结果与浏览器 `mix-blend-mode` 一致（这样两个后端才可能真正对齐）。
- **噪声族**（`noise.py`）：Perlin / Value / Cellular(Worley) / fBm / 域扭曲，全部 NumPy 向量化。
- 4 个自然材质图案：`marble` `clouds` `cracks` `brushed`。

### 新增：场景 DSL（`scene.py` / `ops.py`）
- `Scene` = 尺寸 + 底色 + 图层（每层带 `blend` / `opacity`）；op 参数**扁平**
  （`{"op":"blur","radius":12}`，比 `{"op":...,"args":{...}}` 省 token）。
- 三种语法糖：顶层 `ops`（单层）、裸数组（一层）、顶层 `pattern`（等价旧配方）。
- **构造即校验**：未知动词/图案/键在 `from_dict` 阶段就报错，不留到渲染时。

### 新增：面向 agent 的接口
- `pixsmith spec [--json]`：能力清单（参数类型/默认值/后端支持/最小可用场景）。
- `pixsmith render --report`：自检报告（非透明占比 / 内容包围盒 / 主色 / 亮度 / 对比度）
  —— **agent 看不见图，靠它判断"画对没画对"**。
- **拒绝静默降级**：后端缺能力就报错并给替代方案。

### 架构调整
- 拆出 `backend.py`（后端协议 + 能力校验）、`geometry.py`（几何与渲染分离）、
  `field.py`（参数场）、`params.py`（参数声明公共契约）—— 依赖方向收敛为单向。
- `recipes.render()` 改为走 `Scene`：单图案与多图层不再有两套渲染路径。
- `pattern()` 声明新增 `requires` / `requires_fn`（**参数相关的动态依赖**）。

### 修复
- `fbm` 曾在**每个倍频后各自归一化**再叠加，导致 `persistence=0.5` 时**加倍频反而细节变少**
  （实测相邻差 0.0102 → 0.0084）。改为在原始域叠加、最后只归一化一次。
- 包级导出的 `blend` 函数会**遮蔽同名的 `blend` 子模块**（`from pixsmith import blend`
  拿到函数而非模块）。已改为只导出 `MODES` / `blend_names`。
- 图案里用 `hline`/`vline`（不在后端协议里）会挡住矢量后端；已改为协议方法 `capsule`。
- 契约测试抓出 `SvgBackend` 缺 `w`/`h` 属性 —— 双后端的代价应由后端承担，不该外溢到图案层。

### 测试
- 166 → **283** 个用例。新增：双后端契约、算子数学（含"模糊不渗黑边"）、噪声性质。

## 0.1.0 — 首个版本（2026-09-14）

首个公开版本：把一套用来程序化产出视觉元素的图形代码，做成通用库。

### 新增

- **画布** `Canvas`：8 个图元（`disc` / `ring` / `ellipse` / `rect` / `capsule` / `arc` /
  `polygon` / `erase_disc`），覆盖率抗锯齿（`feather` 与 `ss` 可调），直通道 Alpha 合成。
- **PNG 编码**：标准库 `zlib` + `struct`，无图像库；8 位 RGBA、filter 0、可复现的压缩级别。
- **19 个图案**，分 4 类：`background`(9) · `texture`(3) · `shape`(4) · `festive`(3)。
- **配方（recipe）**：JSON 声明式绘图指令，参数可覆盖、可校验、可回放。
- **CLI** `pixsmith`：`list` / `show` / `render` / `gallery`。
- **测试 166 个**，含与纯 Python 参考实现的**逐像素等价性**校验，
  以及五星红旗的**国标符合性**校验（从像素反测 GB 12982 的星位与指向角）。
- **性能基准** `benchmarks/bench.py`：与纯 Python 参考实现的同工作量对比。

### 相对逐像素原型的改进

- **性能**：逐像素 → NumPy 向量化。实测提升 **6×–42×**（随图元面积增长）。
- **修 bug**：`ring()` 的内边缘羽化。原实现未归一化外圈覆盖率就乘 `(1 - ci)`，
  被截断后内边缘变成硬边（最大差 156/255）。已修正并钉成回归测试。
- **修 bug**：长线段分块合成。分块后重叠带会被合成两次，半透明色会出现一条偏色带。
  改为按参数 `t` 把像素判给唯一分块。
- **去重**：原先散落着 3 份逐像素实现拷贝、`art_stars` 有 3 个版本。现统一到
  `canvas.py` + `patterns/`，参考实现只保留一份用于对照。
- **参数声明化**：图案参数从散落的函数默认值，改为 `Param` 声明
  （类型 / 默认值 / 说明），CLI 帮助与校验都从它生成。
